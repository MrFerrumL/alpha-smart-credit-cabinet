# Пояснение решения простыми словами

Это необязательная функция, по умолчанию она выключена (`LLM_ENABLED=false`). Весь сценарий от подбора кредита до
выдачи работает без неё. Решение принимают правила кредитной политики, модель его не принимает и не меняет.

## Что делает

После автоматического решения (одобрение, другие условия, другой продукт, отказ) воркер просит модель пояснить его.
Первое предложение с условиями пишет код, модель добавляет ещё два: почему так решено и что делать дальше. Опирается
она только на причины и подсказки, которые банк и так показывает клиенту. Ответ проверяется: числа должны совпадать
с решением, а текст не должен спорить с исходом. У клиента пояснение появляется под причинами решения в блоке
«Простыми словами» с пометкой, что оно сформировано автоматически.

Клиент модель не ждёт. Причины и подсказки банка видны сразу, предложение можно принять, пока пояснение готовится.
Если модель недоступна, не ответила за 60 секунд или её ответ не прошёл проверку, клиент видит только причины банка.
К решениям аналитика, отказам по стоп-фактору и запросам документов пояснения нет.

Модели уходят исход, продукт, условия, причины и подсказки. Название компании, реквизиты, ФИО, текст, который ввёл
клиент, балл и пороги политики ей не передаются.

## Какая модель

Условия кейса разрешают только модели с открытыми весами, поэтому модель работает локально или на вашем сервере.
По умолчанию это Qwen2.5-7B-Instruct (лицензия Apache-2.0) в квантовании Q4_K_M, около 4,7 ГБ. Подойдёт и другая
модель с открытыми весами, если её сервер отвечает по OpenAI-совместимому API.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `LLM_ENABLED` | `false` | Включить пояснение |
| `LLM_BASE_URL` | в Docker `http://ollama:11434/v1`, без Docker `http://localhost:11434/v1` | Адрес сервера модели, без `/chat/completions` на конце |
| `LLM_MODEL` | `qwen2.5:7b-instruct-q4_K_M` | Имя модели на сервере |
| `LLM_API_KEY` | пусто | Ключ, если ваш сервер его требует |

Переменные задаются в `.env`. Проверить, что функция включилась: `curl http://localhost:8000/api/meta` вернёт
`"llm_explanation": true`.

## Как запустить

### Ollama на этом ПК

Лучший вариант, если есть видеокарта: модель целиком помещается в 8 ГБ видеопамяти. Без видеокарты Ollama тоже
работает, но медленнее.

1. Установите Ollama с [ollama.com](https://ollama.com/download) и скачайте модель:

   ```bash
   ollama pull qwen2.5:7b-instruct-q4_K_M
   ```

2. Добавьте в `.env`:

   ```
   LLM_ENABLED=true
   LLM_BASE_URL=http://host.docker.internal:11434/v1
   ```

3. Выполните `docker compose up -d --wait`, backend и worker перезапустятся с новыми настройками.

Docker Desktop сам направляет `host.docker.internal` на ваш ПК. На Linux добавьте сервисам backend и worker
`extra_hosts: ["host.docker.internal:host-gateway"]` в `docker-compose.override.yml`, запустите Ollama с
`OLLAMA_HOST=0.0.0.0` и закройте порт 11434 снаружи файрволом. Без Docker адрес по умолчанию уже указывает на
локальную Ollama, достаточно `LLM_ENABLED=true`.

### Профиль `llm` в Docker

Сервис `ollama` запускается вместе со стендом и работает на процессоре. Модели нужно около 5 ГБ памяти, поэтому
профиль рассчитан на ПК с 16 ГБ; на 8 ГБ его лучше не включать. В `.env`:

```
COMPOSE_PROFILES=llm
LLM_ENABLED=true
```

```bash
docker compose up --build -d --wait --wait-timeout 1800
```

При первом запуске сервис скачивает образ и модель, это может занять долгое время. Наружу порт Ollama не
открывается, воркер обращается к ней внутри сети compose.

### Свой сервер

Если модель с открытыми весами уже работает на другой машине (vLLM, сервер llama.cpp или Ollama), укажите её
адрес в `LLM_BASE_URL`, имя в `LLM_MODEL` и, если сервер этого требует, ключ в `LLM_API_KEY`. Данные решения
(см. выше) будут уходить на эту машину.

## Как выключить

Уберите из `.env` строки `LLM_ENABLED=true` и `COMPOSE_PROFILES=llm` и выполните `docker compose up -d --wait`.

Контейнер ollama после этого продолжит работать: `up` и `down` без профиля не трогают ни его, ни его том с моделью.

- Остановить его: `docker compose --profile llm stop ollama`.
- Удалить стенд вместе с томом модели (и с базой): `docker compose --profile llm down -v`.
- Удалить только модель: `docker compose --profile llm rm -sf ollama`, затем `docker volume rm alpha-credit_ollama`.

Модель в Ollama на ПК удаляется командой `ollama rm qwen2.5:7b-instruct-q4_K_M`.

## Насколько быстро

На ноутбуке с видеокартой на 8 ГБ ответ приходит примерно за 2 секунды, и почти всегда быстрее 3 секунд; проверку
прошли 48 ответов из 51. На процессоре заметно медленнее. Подробности и примеры ответов в
[llm-benchmark.md](llm-benchmark.md).

Замерить на своей модели (скрипт берёт адрес и модель из `LLM_*`):

```bash
docker compose exec worker python -m app.explanation.bench --runs 3
```
