# Замер пояснения решения на локальной модели

Замер 24.10.2026 скриптом `python -m app.explanation.bench --runs 3` (раздел README «Пояснение решения простыми
словами»). Скрипт строит 17 решений той же кредитной логикой, что и конвейер, по всем веткам, и вызывает модель с
тем же промптом, проверкой ответа и таймаутом, что и воркер. База и эмулятор не нужны.

причины и подсказки банка.

## Почему промпт `explain-2`

Первый промпт (`explain-1`) настраивали под модель 4B. На Qwen2.5-7B с ним проверку прошли **6 из 51 (12 %)** при
p50 2,4 с и p95 3,5 с: модель писала «условия договора», «получить средства», «шансы на одобрение» и повторяла
сумму и ставку из первого предложения — проверка это отбрасывает (`invalid:outcome` ×27, `invalid:numbers` ×8).
Во второй версии ответ — два предложения фиксированной формы: «Главное: …» повторяет причины этого решения теми же
словами, второе предложение пересказывает следующий шаг (при отказе — с действия, при предложении — с «Если всё
подходит»); слова, которые отбрасывает проверка, названы прямо. Проверка ответа не менялась.

Пример содержания в промпте не используется: в промежуточной версии модель переносила пример в чужие решения
(«платежи займут небольшую часть выручки» там, где причина — лимит по выручке), и проверка это пропускала.

## Как повторить

```bash
ollama serve                                   # Ollama 0.40.2; на видеокарте NVIDIA модель встанет на GPU сама
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama ps                                      # после первого запроса: 100% GPU
cd backend
LLM_BASE_URL=http://127.0.0.1:11434/v1 .venv/Scripts/python -m app.explanation.bench --runs 3
```

В Docker с профилем `llm`: `docker compose exec worker python -m app.explanation.bench --runs 3` — там модель
работает на процессоре, и время ответа будет заметно больше.
