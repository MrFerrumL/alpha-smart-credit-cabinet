# Model card: synthetic-risk-logreg-v2

## Назначение и данные

Учебная модель демонстрирует ML engineering: данные → split → preprocessing → обучение → оценка → экспорт → inference.
API возвращает `experimental=true` и `affects_credit_decision=false`. Прогноз отображается аналитику,
но не подключён к кредитной политике.

Генератор `backend/scripts/train_risk.py` создаёт 12 000 независимых строк, seed=42. Показатели синтетические.
Цель — смоделированный индикатор дефолта в условном горизонте 12 месяцев: Bernoulli-выборка из заданной
логистической вероятности. Это учебная зависимость без реального наблюдения дефолтов, цензурирования и времени.
В dataset v2 около 65% строк имеют нулевой налоговый долг; остальные получают положительное значение из
экспоненциального распределения. Это устраняет предупреждение о нуле только из-за отсутствия нулей в обучении v1.

| Признак | Единицы и контракт API |
|---|---|
| business_age_years | Возраст бизнеса, 0–100 лет |
| dsr | Месячные платежи / месячная выручка, 0–5 |
| margin | (Выручка − расходы) / выручка, −1–1 |
| max_overdue_days_24m | Максимальная историческая просрочка, 0–730 дней |
| inquiries_90d | Запросы в БКИ за 90 дней, 0–100 |
| tax_debt_ratio | Налоговый долг / годовая выручка, 0–10 |
| has_credit_history | Boolean: есть ли кредитная история |

Все поля обязательны; неизвестные поля, строки вместо чисел, NaN/Infinity и выход за границы отклоняются.
Границы API шире типичных значений генератора: принятие запроса не означает достоверную экстраполяцию.
`out_of_training_range` перечисляет признаки вне минимумов/максимумов train. Это простой контроль диапазонов,
не полноценный OOD-детектор: необычные комбинации и изменение распределения внутри границ он не обнаруживает.

## Обучение и оценка

Стратифицированный split: train 7 200, validation 2 400, test 2 400. StandardScaler обучен только на train.
LogisticRegression: `C=1`, `max_iter=1000`, гиперпараметры заданы заранее. Target, решение правил и идентификаторы
не входят в признаки. Отдельные организации и время не моделируются.

Порог **0.11** выбран только на validation из сетки 0.05–0.95 с шагом 0.01: минимизируется
`(5 × FN + FP) / N`. Стоимости ошибок условные, порог не является банковской рекомендацией.
Test не участвует в подборе порога или гиперпараметров.

На test: ROC-AUC **0.7842**, Average Precision **0.4540**, Brier **0.1013**, log loss **0.3385**.
Положительный класс: **14.42%**. Baseline выдаёт долю дефолтов **train**; ROC-AUC 0.5, Brier 0.1234, log loss 0.4125.
При пороге 0.11: TN=1341, FP=713, FN=87, TP=259. Полный отчёт с calibration bins:
[evaluation.json](../backend/app/ml/artifacts/evaluation.json).
Доверительные интервалы, временная валидация и fairness-анализ не рассчитывались.

## Экспорт и serving

JSON schema v2 содержит порядок признаков, средние, масштабы, коэффициенты, intercept, порог и диапазоны train.
Артефакт валидируется Pydantic-контрактом: числа конечны, размерности согласованы, масштабы положительны,
порядок признаков точный, неизвестные поля запрещены. После загрузки параметры неизменяемы.
API валидирует артефакт и считает устойчивую sigmoid от суммы вкладов в log-odds без scikit-learn или pickle.
SHA-256 связывает ответ с весами; это идентификатор содержимого, не цифровая подпись.
Вклады объясняют вычисление, но не причинность, и не являются SHAP-значениями.

Обучающий скрипт сравнивает переносимый inference со scikit-learn на всех 2 400 test-строках: расхождение `<1e-12`.
CI повторяет обучение и сравнивает коэффициенты с допуском 1e-8 на платформенные различия.
Зависимости обучения зафиксированы в requirements-ml.txt. JSON кэшируется в процессе API;
после замены артефакта требуется перезапуск.

## Прогноз по заявке

`GET /api/applications/{id}/ml-risk` читает последний `ScoringResult` по id и использует его `features`.
Текущая анкета не участвует: признаки соответствуют конкретной сохранённой оценке. Поля `scoring_id` и
`scored_at` связывают ответ с источником; timestamp явно передаётся в UTC, включая SQLite-стенд.
`tax_debt_ratio = tax_debt / revenue_monthly / 12`. При неполных или некорректных значениях прогноз отсутствует.
Запрос не создаёт новых строк в БД и не меняет версию заявки. Поэтому это просмотр экспериментальной оценки,
а не постоянный журнал shadow-прогнозов. Отдельный журнал и drift monitoring пока не реализованы.

## Ограничения и развитие

Качество получено только на синтетике, причём логистический generator благоприятен для Logistic Regression.
Модель не валидирована на реальных клиентах и не готова к выдаче кредитов. Для продолжения нужны реальные
обезличенные наблюдения с определённым горизонтом target, временной split, оценка по сегментам, проверка смещения,
мониторинг качества и процесс допуска/отката модели.
