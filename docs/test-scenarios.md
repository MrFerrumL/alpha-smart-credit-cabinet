Ручная проверка «Потока» на демо-данных: сквозные сценарии в интерфейсе, права ролей и отказоустойчивость.
Ожидаемые результаты сверены прогоном конвейера на коде из `main` (commit `f54bae1`). У каждого сценария
указан автотест, который закрепляет то же поведение, если он есть.

**Подготовка.** `docker compose down -v && docker compose up --build` — чистая база с демо-данными.
Кабинет — http://localhost:8080, вход в один клик на странице входа, пароль у всех учёток — `demo1234`.
Swagger — http://localhost:8000/api/docs, эмулятор источников — http://localhost:8001/docs.

## Сквозные сценарии в интерфейсе

### TS-01. Одобрение и путь до денег — `bakery@demo.local`

1. Войти как Ольга Северова, ООО «Северная пекарня».
2. Подбор: цель «Пополнить оборотные средства», 3 000 000 ₽, 12 мес. Первым показан «Экспресс-оборот» с
   платежом и графиком.
3. Анкета: компания подставлена из ЕГРЮЛ; выручка в месяц — 4 500 000 ₽ из данных ФНС за 2025 год;
   отметить согласие на запрос в БКИ; отправить.
4. Ожидаемо: этапы на таймлайне сменяются без перезагрузки — «Проверяем данные» → «Проверяем компанию» →
   «Оцениваем заявку» → «Одобрено».
5. Решение: 3 000 000 ₽, 12 мес., 22,9%, платёж 282 084 ₽. Причины: «Компания давно на рынке — 8 лет»,
   «Платежи по кредитам займут небольшую часть выручки», «Кредиты обслуживаются без просрочек».
6. «Принять и перейти к договору» → статус «Подписание договора». Договор с номером `КД-2026-…` и графиком.
7. Отметить ознакомление → «Подписать кодом» → код из колокольчика → подпись.
8. Ожидаемо: через несколько секунд «Деньги зачислены»; в «Мои кредиты» — 3 000 000 ₽, 12 платежей,
   ближайший платёж; уведомление о зачислении.

### TS-02. Бухгалтер готовит, директор подписывает — `buh@`, затем `bakery@`

1. `buh@demo.local` (Елена Счётова, без права подписи) создаёт и отправляет заявку на «Экспресс-оборот»,
   1 000 000 ₽, 12 мес.
2. Ожидаемо: решение «Одобрено». Кнопки «Принять» нет, есть «Отказаться» и «Отозвать».
3. Через API `POST /api/applications/{id}/offer/accept` от бухгалтера → `403`, в тексте — что принять может
   руководитель.
4. `bakery@demo.local` видит ту же заявку, принимает и подписывает.

### TS-03. Контрпредложение — `sklad@demo.local`

2. Ожидаемо: «Есть предложение» — 4 500 000 ₽, 12 мес., 22,9%, платёж 423 126 ₽. Объяснение: «Сумма

### TS-04. Запрос выписки — `smirnova@demo.local`

1. «Экспресс-оборот», **500 000 ₽**, 12 мес.; выручка в анкете — 600 000 ₽; выписку не прикладывать; отправить.
2. Ожидаемо: «Нужна информация», запрос «Загрузите выписку по расчётному счёту» — в налоговой нет данных о

3. Загрузить PDF по запросу. Статус сам возвращается в «Проверяем данные», затем «Одобрено».

## Отказоустойчивость

Сбои включаются в эмуляторе: `POST http://localhost:8001/admin/faults`. Сброс:
`{"source":"all","mode":"none"}`.

### TS-11. Короткий сбой БКИ

```bash
curl -X POST localhost:8001/admin/faults -H "Content-Type: application/json" -d '{"source":"bki","mode":"error","count":2}'
```

Отправить заявку `bakery@` (TS-01). Ожидаемо: в истории `check_retry`, итог — «Одобрено».

### TS-12. Долгий сбой БКИ

То же без `count`. Ожидаемо: «Рассматривает специалист», первая причина упоминает бюро кредитных историй;
проверки: ЕГРЮЛ — `ok`, ФНС — `ok`, БКИ — `failed`. Заявка не теряется и не падает с ошибкой.

### TS-13. Сбой АБС при выдаче

После подписания (TS-01, шаг 7) включить `{"source":"abs","mode":"error","count":1}`. Ожидаемо: в истории
`disbursement_retry`, затем `issued`; кредит один — номер договора служит ключом идемпотентности.

### TS-19. Масштабирование воркеров

`docker compose up --build --scale worker=3`, отправить несколько заявок с разных учёток подряд. Ожидаемо:
каждая доходит до решения ровно один раз, в истории нет повторяющихся шагов.

## Подписание, отзыв и сроки

### TS-14. Неверный и устаревший код

1. Принять предложение, запросить код, ввести неверный → `422`, «Осталось попыток: 2».
2. Запросить новый код — старый перестаёт работать (`409`).
3. Три неверных ввода нового кода → дальше даже верный код отклоняется (`409`); заявка остаётся в «Подписание
   договора», можно запросить новый код.
4. Код действует 5 минут (`SIGNING_CODE_TTL_S=300`).

### TS-15. Отказ от предложения и отзыв

1. По одобренной заявке «Отказаться» с комментарием → «Заявка отозвана»; принять потом — `409`.
2. Отозвать заявку можно на любом этапе до подписания; после подписи отзыв — `409`.

### TS-16. Истёкшее предложение

Предложение действует 7 дней (`OFFER_VALID_DAYS`); воркер закрывает просроченные раз в минуту.
Вручную ждать неделю не нужно — поведение закреплено автотестом: статус `expired`, принять — `409`.

## Права и валидация

### TS-17. Изоляция и права

- `sklad@` открывает заявку «Северной пекарни» по прямой ссылке или через API → `404`.
- Поток статусов чужой заявки (`/stream`) → `404`.
- `analyst@` пытается создать заявку → отказ; аналитик видит только отправленные заявки, без черновиков.
- Запрос без токена → `401` в едином формате ошибок.

### TS-18. Валидация

- Отправка без согласия на БКИ → `422`, поле `form.consent_bki`.
- Сумма или срок вне рамок продукта, например «Экспресс-оборот» на 200 000 ₽ → `422`.
- Загрузка `virus.exe` вместо выписки → `422`; допустимы PDF, PNG, JPG, XLSX, XLS, CSV, DOC, DOCX, TXT до 10 МБ.
