# Поток — запуск и проверка решения

Всё, что нужно, чтобы запустить и проверить решение: версия, запуск одной командой, демо-учётные записи,
основной сценарий, документы и известные ограничения.

## 1. Что это

«Поток» — прототип умного кредитного кабинета для малого бизнеса (Альфа-Хакатон 2026, кейс «Умный кредитный
кабинет предпринимателя»). Предприниматель в веб-кабинете подбирает кредит под задачу бизнеса, подаёт заявку и
в реальном времени видит, что с ней происходит. Банк проверяет данные, обогащает их из ЕГРЮЛ/ЕГРИП, ФНС
«Прозрачный бизнес» и бюро кредитных историй, оценивает риск и принимает решение — автоматически или руками
кредитного аналитика, — а после подписи договора одноразовым кодом выдаёт кредит; весь путь проходит в одном
кабинете, без почты, SMS и мессенджеров. Скоринг и решение — объяснимые правила; внешние системы эмулируются на
синтетических данных. Моделей машинного обучения, LLM и платных сервисов в решении нет.

```bash
git fetch --tags
git rev-parse v1.0.0^{commit}
git checkout v1.0.0
```

## 3. Запуск

### Что нужно

- Docker: Docker Desktop на Windows или macOS, Docker Engine с Compose v2 на Linux; процессор x86-64 или arm64.
- Свободные порты 8080, 8000 и 8001.
- Интернет для первой сборки образов; дальше стенд работает без интернета.
- Python 3.10+ — только для необязательной дымовой проверки, сторонние пакеты не нужны.

### Ресурсы

<!--RESOURCES-->
- **Работает на обычном ПК с 8 ГБ памяти без видеокарты.** Видеокарта не используется: моделей машинного обучения
  в решении нет.
- Память: все контейнеры стенда вместе занимают не больше 235 МиБ в один момент. Сумма пиков по контейнерам —
  322 МиБ; это оценка сверху, вместе с кэшем файлов.
- На Windows и macOS к этому добавляется виртуальная машина Docker Desktop, обычно 1–2 ГБ.
- Диск: около 3 ГБ. Это образы вместе с промежуточными слоями сборки (2,4 ГБ), кэш сборки (0,15 ГБ) и данные
  (0,05 ГБ). Образы самого стенда: backend и worker — 205 МБ (один образ), postgres — 276 МБ, mocks — 142 МБ,
  frontend — 49 МБ.
- Где измерено: раннер CI с 2 vCPU и 7,9 ГБ памяти, без видеокарты. На нём же шли сборка, стенд и все сценарии.
  Отчёт о ресурсах — в артефакте `resources` каждого прогона CI.
- Первая сборка образов занимает 3–6 минут.
<!--/RESOURCES-->

### Запуск одной командой

```bash
git clone https://github.com/donaldtrumpdev-commits/alpha.git
cd alpha
docker compose up --build
```

- Чтобы запустить именно проверяемую версию, перед `docker compose` выполните `git checkout v1.0.0`.
- Чтобы команда вернула управление, когда все сервисы готовы (healthcheck, включая «пульс» воркера
  конвейера): `docker compose up --build -d --wait`. После неё кабинет открыт.
- Файл `.env` не нужен: у всех переменных есть безопасные для демо значения (см. `.env.example`).
- При первом запуске применяются миграции и загружаются синтетические демо-данные; вместе с API стартует воркер
  конвейера. Стенд стартует без заявок.
- Начать с чистыми данными: `docker compose down -v`, затем снова `docker compose up --build -d --wait`.

### Адреса и порты

| Что | Адрес | Доступ |
|---|---|---|
| Кабинет клиента и банка | http://localhost:8080 | из сети; кабинет ходит в API через nginx |
| API и Swagger | http://localhost:8000/api/docs | только с этой машины (`127.0.0.1`) |
| Эмулятор ЕГРЮЛ/ФНС/БКИ/АБС | http://localhost:8001/docs | только с этой машины (`127.0.0.1`) |

PostgreSQL наружу не открыт.

### Проверка, что стенд работает

```bash
python scripts/smoke.py
```

В Windows Python может называться `py`, в Linux и macOS — `python3`. Скрипт проверяет готовность (`/health/ready`),
входит как `bakery@demo.local`, подаёт заявку на 3 000 000 ₽ на 12 мес. и ждёт одобрения; при успехе печатает
`OK: application approved`.

## 4. Демо-учётные записи

На странице входа http://localhost:8080 поле «Почта» открывает список демо-профилей: у каждого — компания и
исход сценария, аналитик банка — в том же списке. Выбранный профиль подставляет почту и пароль, остаётся
«Войти»; пароль у всех `demo1234`. У каждой вкладки браузера свой вход, поэтому клиента и аналитика можно открыть рядом. Ссылка на
страницу кабинета, открытая в новой вкладке, сначала ведёт на вход, а после входа — на главную: нужную заявку
откройте из списка.

Как подать заявку: «Подобрать кредит» → цель, сумма, срок → «Оформить заявку» у продукта → анкета по шагам →
согласие на запрос в БКИ → «Отправить в банк». Данные компании и выручка из ФНС подставляются в анкету сами.
«Экспресс-оборот» открывается целью «Пополнить оборотные средства», «Инвестиционный кредит» — целью «Купить
оборудование или транспорт».

## 5. Основной сценарий по шагам

Откройте кабинет http://localhost:8080 в двух вкладках одного браузера: вкладка **А** — клиент, вкладка
**Б** — банк. Очередь аналитика и симулятор политики наполняются по мере шагов 1–4. Весь сценарий занимает
около 10 минут; пройти его заново с чистыми данными: `docker compose down -v`, затем
`docker compose up --build -d --wait`.

Видео основного сценария — артефакт `demo-video` прогона CI (Actions → прогон → Artifacts); файл хранится
30 дней и открывается после входа в GitHub, поэтому его стоит приложить к форме сдачи отдельно.

1. **Одобрение и выдача (2,5 мин).** А: войти как Ольга Северова (`bakery@`) → «Подобрать кредит» →
   «Пополнить оборотные средства», 3 000 000 ₽, 12 мес. → «Оформить заявку» у «Экспресс-оборота» → пройти
   анкету (данные компании и выручка подставлены) → согласие на запрос в БКИ → «Отправить в банк». Заявка
   проходит этапы на глазах и примерно через 10 с одобряется. «Принять предложение» → отметить ознакомление
   с договором → «Подписать кодом» → ввести код из окна подписания → «Деньги на счёте!», кредит и график
   в «Мои кредиты».
   На главной — «Новости для вас» под пекарню; у «ТехноСклада» и «Вектора» лента другая.
2. **Контрпредложение (1 мин).** А: выйти и войти как Дмитрий Орлов (`sklad@`) → «Экспресс-оборот»,
   10 000 000 ₽, 12 мес. → контрпредложение 4,5 млн на 16 мес. со сравнением «вы просили → банк предлагает».
   Другим продуктом: Лариса Тихонова (`clean@`) → «Экспресс-оборот», 300 000 ₽, 12 мес. → банк предлагает
   «Овердрафт» на 150 тыс.
3. **Ручное решение, видимое клиенту (3 мин).** А: Игорь Волков (`vector@`) → «Купить оборудование или
   транспорт» → «Инвестиционный кредит», 25 000 000 ₽, 48 мес., залог — оборудование, 30 000 000 ₽ →
   отправить → «Рассматривает специалист». Б: войти как Мария Кредитова (`analyst@`) → заявка в очереди
   «Ждут решения» → карточка: грейд C, факторы, стоп-факторы, «просит → предлагает», трасса правил →
   «Воспроизвести решение» → «Совпадает». Форма решения уже заполнена контрпредложением 19,5 млн на 60 мес.: написать
   обоснование → «Сохранить решение». А: статус меняется сам → принять → появляются условия выдачи →
   подписать кодом → загрузить любой PDF как документ по залогу и ответить на вопрос о поручительстве →
   деньги зачислены.
4. **Отказ и запрос информации (1,5 мин).** А: Павел Быстров (`start@`) → «Экспресс-оборот», 2 000 000 ₽ →
   отказ с причинами и подсказками. Анна Смирнова (`smirnova@`) → 500 000 ₽, 12 мес., выручка 600 000 ₽ →
   банк просит выписку → загрузить PDF → заявку сверяет специалист (Б: «Одобрить» с обоснованием). Пока банк
   ждёт выписку, наверх ленты «Новости для вас» поднимается новость о дополнительных документах.
5. **Отказоустойчивость (1 мин).** «Уронить» бюро кредитных историй на три ответа и отправить любую заявку
   пекарни: в истории раскрыть «Автоматические проверки» — там «Бюро кредитных историй: нет ответа — повторяем
   запрос», затем решение.

   ```bash
   curl -X POST localhost:8001/admin/faults -H "Content-Type: application/json" -d '{"source":"bki","mode":"error","count":3}'
   ```

   В Windows PowerShell (там `curl` — другая команда):

   ```powershell
   Invoke-RestMethod -Method Post -Uri http://localhost:8001/admin/faults -ContentType 'application/json' -Body '{"source":"bki","mode":"error","count":3}'
   ```

6. **Политика (1 мин).** Б: «Кредитная политика» (считает заявки, поданные в шагах 1–5) → сдвинуть пороги →
   «Рассчитать»: какие заявки изменили бы исход и как сдвинулись доля положительных решений и объём. Заявки при
   этом не меняются.

Полный список сценариев с точными данными, негативные и ролевые проверки — в
[docs/test-scenarios.md](https://github.com/donaldtrumpdev-commits/alpha/blob/v1.0.0/docs/test-scenarios.md).

## 7. Автоматические проверки

На каждый push в `main` и `feat/**` и на pull request GitHub Actions (`.github/workflows/ci.yml`) прогоняет
144 автотеста backend на PostgreSQL по схеме из миграций, сверяет с кодом спецификацию OpenAPI, диаграмму состояний и
коллекцию запросов и собирает фронтенд. Затем стенд поднимается с нуля командой
`docker compose up --build -d --wait`, и на нём проходят дымовой сценарий, коллекция запросов через newman и
12 сценариев демо-учёток в браузере (Playwright). Те же проверки можно запустить локально:

```bash
# Автотесты backend: Python 3.12, из папки backend
pip install -r requirements-dev.txt
python -m pytest -q
```

```bash
# Сквозные проверки поднятого стенда: Node.js 22, из папки e2e
npm ci
npx playwright install chromium
npm run api    # коллекция запросов через newman
npm run ui     # сценарии в браузере, на чистом стенде
```

## 8. Известные ограничения

- Подключить компанию через кабинет может только её руководитель или учредитель по ЕГРЮЛ (в прототипе —
  сверка по ФИО): из демо-учёток это `new@` с ИНН `0077070071`. Профили риска других ИНН с «00» проверяются
  автотестами, карточку такой компании можно получить через API (`GET /api/companies/lookup?inn=…`).
- Аналитик не может предложить другой продукт (это делает только конвейер); срока на закрытие условий выдачи нет.
- Продукты, ставки и пороги политики условные. ЕГРЮЛ/ЕГРИП, ФНС, БКИ и АБС эмулируются, контракты упрощены.
- Покрытие прибылью считается для нового платежа — упрощённый показатель, а не полный DSCR.
- Выписка по счёту не разбирается: заявку с выручкой только по выписке всегда сверяет специалист. Загруженные
  файлы банк видит списком (имя и размер), просмотра файла в кабинете аналитика нет.
- Подпись смоделирована: одноразовый код показывается в окне подписания, SMS и почта не используются.
- Овердрафт оформляется как кредит с ежемесячной уплатой процентов и возвратом долга в конце срока, а не как
  лимит на счёте с траншами.
- Лента «Новости для вас» — синтетические новости, внешних источников нет.
- Публичный стенд не развёрнут.
- Сценарии в браузере (`npm run ui`) меняют данные стенда (`new@` подключает компанию один раз), поэтому
  повторный прогон — после `docker compose down -v` и нового `up`.
