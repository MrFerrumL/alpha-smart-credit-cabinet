# Путеводитель для Backend / ML интервью

| Тема | Где смотреть | Что обсуждать |
|---|---|---|
| API и доступ | `backend/app/api`, `security.py` | JWT, роли, валидация, ошибки, OpenAPI |
| Консистентность | `services/state_machine.py`, `pipeline/queue.py` | Транзакции, повторы, идемпотентность |
| Интеграции | `services/integrations.py`, `mocks/` | Таймауты, backoff, circuit breaker |
| ML experiment | `scripts/train_risk.py` | Stochastic target, split, leakage, baseline, порог |
| Model serving | `app/ml/inference.py`, `app/api/ml.py` | Feature contract, parity, JSON, log-odds |
| Проверки | `tests/test_ml.py`, `ml_tests/test_training.py` | Права, плохие данные, экспорт, воспроизводимость |

## Что было и что добавлено

Исходный проект уже содержал продуктовый сценарий, Backend, React, PostgreSQL, worker, правила политики и CI.
Портфолио-доработка добавляет обучаемую модель, offline evaluation, JSON inference, аналитический API и ML-тесты.
Источник и базовый commit — в [PROVENANCE.md](../PROVENANCE.md).

## Демонстрация на 7–10 минут

1. Поднять Compose, войти клиентом, подать заявку и показать путь до выдачи.
2. Войти аналитиком и объяснить работу с исключениями.
3. Через Swagger вызвать `/api/ml/model` и `/api/ml/predict` под ролью аналитика.
4. Увеличить dsr и историческую просрочку: сравнить вероятность и вклады.
5. Открыть отчёт, объяснить split, baseline, стоимость FN/FP и ограничения синтетики.
6. Показать тест training-serving parity и разделение зависимостей обучения/API.

## Формулировка для описания проекта

«Учебный кредитный кабинет для малого бизнеса на FastAPI, PostgreSQL и React. Портфолио-версия расширяет
хакатонный прототип моделью риска: воспроизводимое обучение Logistic Regression, валидация признаков,
оценка на отложенной синтетической выборке, JSON inference и API с разграничением доступа».

Добавьте свой подтверждаемый вклад. Не приписывайте себе разработку всей исходной системы, работу в Альфа-Банке,
промышленную эксплуатацию или результаты на реальных банковских данных. ROC-AUC 0.80 относится к синтетике.

## Компромиссы и развитие

- Очередь в PostgreSQL упрощает транзакционность MVP; масштабирование требует измерений.
- Линейная модель удобна для прозрачного экспорта; логистический generator создаёт благоприятные для неё данные.
- ML API принимает явные признаки; автоматический feature adapter и shadow-журнал ещё не реализованы.
- Порог выбран на validation; перенос на реальные данные потребует отдельной проверки и калибровки.
- Для production нужны управление секретами, резервное копирование, мониторинг, нагрузочные проверки
  и независимая валидация модели.
