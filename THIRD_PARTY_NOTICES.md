# Сторонние компоненты

Перечень сторонних библиотек, образов, сервисов, моделей и данных, используемых в проверяемой версии решения,
и указание смоделированных интеграций. Версии и лицензии сверены с зафиксированными зависимостями
(`backend/requirements.txt`, `mocks/requirements.txt`, `backend/requirements-dev.txt`,
`frontend/package-lock.json`); лицензии Python-пакетов взяты из метаданных установленных пакетов, лицензии
npm-пакетов — из поля `license` в `frontend/package-lock.json`.

**Платных сервисов, платных API, купленных данных и закрытых лицензий решение не использует.**
Все компоненты имеют открытые лицензии. Копилефт-лицензий сильного типа (GPL, AGPL, SSPL) в зависимостях решения
нет; слабый копилефт (LGPL-3.0, MPL-2.0) отмечен отдельно.

## Инфраструктура (Docker-образы)

Образы берутся с Docker Hub в виде официальных, версии зафиксированы. Образы используются как среда выполнения
без изменений содержимого; базовые ОС (Debian, Alpine) содержат собственные системные пакеты под своими
лицензиями (в том числе GPL — например, busybox, coreutils), которые не линкуются с кодом решения и не
распространяются отдельно от образов.

|---|---|---|
| PostgreSQL 16 (образ `postgres:16.9-alpine`) | PostgreSQL License | Основная БД (также в CI) |

| Python (образ `python:3.12.11-slim-bookworm`) | PSF License (PSF-2.0) | Среда выполнения backend и эмулятора |
| Node.js (образ `node:22.16.0-alpine`, только сборка) | MIT | Сборка фронта; в итоговый образ не входит |

## Смоделированные интеграции

Решение не обращается к реальным внешним системам. Все интеграции воспроизводит сервис `mocks` на
синтетических данных, контракты упрощены с сохранением смысла:

| Реальный источник | Что эмулируется | Эндпоинт эмулятора |
|---|---|---|
| ЕГРЮЛ / ЕГРИП (ФНС России) | Регистрационные данные, статус, ОКВЭД, руководитель, учредители | `GET /egrul/{inn}` |
| Бюро кредитных историй | Действующие обязательства, платежи, просрочки, число запросов | `GET /bki/{inn}` |
| ФНС «Прозрачный бизнес» | Выручка, расходы, налоги, задолженность, численность, признаки риска | `GET /fns/{inn}` |
| АБС банка (выдача кредита) | Перевод суммы кредита на счёт клиента, идемпотентность по номеру договора, ответ с идентификатором платежа и статусом `executed`; реальных переводов денег нет | `POST /abs/disbursements` |
| Подписание документов | Простая электронная подпись одноразовым кодом, показанным в окне подписания, внутри продукта (смоделировано); квалифицированная подпись и внешние сервисы подписания не используются | — |
| Новостная лента | 24 синтетические новости с тегами по ОКВЭД, продукту, правовой форме, региону и статусу заявки (`backend/app/data/news.json`), помечены в интерфейсе как смоделированные; внешние новостные источники не подключаются | `GET /api/feed` (backend) |

Для проверки устойчивости эмулятор поддерживает имитацию сбоев источников и задержек
(`POST /admin/faults`, `GET /admin/faults`, переменная `MOCK_LATENCY_MS`). Это служебный интерфейс эмулятора,
отдельной интеграцией он не является.

## Данные

Используются только синтетические данные, подготовленные командой. Готовые наборы данных (датасеты) других
авторов, купленные данные и реальные персональные данные не применяются.

Все компании, люди, ИНН/ОГРН и финансовые показатели вымышлены. ИНН начинаются с «00» — такого кода
региона не существует, совпадения с реальными организациями исключены. Для ИНН вне демо-набора эмулятор
генерирует данные детерминированно, с профилем риска по девятой цифре ИНН (`mocks/mockapi/generator.py`):

| Девятая цифра ИНН | Профиль |
|---|---|
| 0–4 | благополучная компания |
| 5 | низкая рентабельность |
| 6 | высокая долговая нагрузка |
| 7 | текущая просрочка |
| 8 | налоговая задолженность и массовый адрес регистрации |
| 9 | компания не действует (ликвидация, реорганизация или банкротство) |

## Модели машинного обучения и LLM

Модели машинного обучения и большие языковые модели (LLM) в решении **не используются**: ни при обучении,
ни при работе. Решение не вызывает внешних ML- и LLM-сервисов, не содержит весов моделей и не применяет
сторонних датасетов, кроме синтетических данных команды (раздел «Данные»). Решения по заявкам принимаются
по явным правилам кредитной политики, которые можно просмотреть и воспроизвести в интерфейсе.

## Платные и закрытые компоненты

Платных подписок, платных API, купленных данных, закрытых (проприетарных) лицензий и сервисов, требующих
регистрации или ключей доступа, решение не использует. Все перечисленные компоненты распространяются под
открытыми лицензиями, а образы Docker и пакеты загружаются из публичных реестров.
