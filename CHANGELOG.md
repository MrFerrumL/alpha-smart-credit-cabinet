# История изменений

## 1.0.2 — 26.10.2026

Для клиента:

- Карта одобрения: после контрпредложения и отказа без стоп-фактора кабинет показывает, сколько банк одобрит по тому же
  продукту на каждом сроке, и «Оформить на этих условиях» создаёт новую заявку с готовой анкетой. Суммы считаются теми же
  правилами, что и решение (`GET /api/applications/{id}/approval-map`). Новая заявка с карты после подтверждения
  заменяет действующее предложение, чтобы одобрения на одних данных не копились.
- Анкета сама сохраняет черновик через секунду после правки и при уходе с шага, открывается на первом незаполненном
  шаге, ставит фокус на ошибку. На шаге «Финансы» видно, что проверит банк: нагрузка до 50 % выручки, лимит продукта в
  месячных выручках, покрытие платежа прибылью от 1,2.
- Кнопка в карточке заявки на подписании следует правам: «Подписать договор», «Закрыть условия выдачи» или «Открыть
  заявку». Диалог отзыва называет сумму и срок предложения, которые перестанут действовать; черновик закрывается без
  отправки, и банк его не видит.
- Отказ специалиста без подсказки не выглядит как отказ по стоп-фактору: в решении есть признак `stop_factor`.
- Ошибка `409` читается понятно («Действие сейчас недоступно», «Заявка уже в статусе «…» — показали актуальное
  состояние»), и экран перечитывает заявку. Подсказки говорят «в заявке» вместо «ниже».
- Пока банк проверяет заявку, на странице есть панель «Ваша заявка». Подписание ждёт загрузки договора, код подписи не
  дублируется всплывающим сообщением, на главной одно последнее уведомление по заявке.
- Лента «Новости для вас» (дополнительная функция, в требования кейса она не входит): этап главной заявки такой же, как
  на главной странице, новость этапа всегда первая, с меткой «По вашей заявке» и ссылкой на следующий шаг; над лентой
  строка «Подобрано для …». Новые синтетические новости на проверку, одобрение, подписание, выдачу и для раздела «услуги
  населению». В ответе ленты появилось поле `application_id`.

Для банка:

- Карточка аналитика: сводка «Почему у вас», «Конвейер рекомендует», «Расхождения» (выручка отличается от ФНС больше
  чем на 10 %, платежи по БКИ не указаны в анкете), блок «Запросы и документы», предпросмотр «Клиент увидит» и
  предзаполненное сообщение клиенту. После решения видны «Предложено», статус предложения и «Решение: …». Пока заявка
  ждёт решения, трасса правил раскрыта.
- Страница «Состояние системы» (`/system`): источники, очередь конвейера, последние повторы и сбои шагов с причиной
  простыми словами (`GET /api/system/jobs`, только аналитик, без ИНН).

Надёжность и безопасность:

- Предохранитель по каждому источнику: после пяти сбоев подряд запросы к нему на 20 секунд приостанавливаются, затем идёт
  один пробный (`BREAKER_THRESHOLD`, `BREAKER_COOLDOWN_S`). В истории заявки: «… недоступен — запросы приостановлены,
  повторим автоматически».
- `GET /health/deps`: версия, очередь конвейера и состояние источников (`ok` или `paused`); на готовность не влияет.
- Сквозной `X-Request-ID` доходит до эмулятора; шаги воркера идут под `job-<id>.<попытка>` с `application_id`; ИНН
  в журнал интеграций не попадает.
- Повторное подтверждение подписи тем же кодом возвращает `200`. Выдача в АБС идёт с `Idempotency-Key`, эмулятор отвечает
  `409` на тот же ключ с другими реквизитами.
- nginx: `Content-Security-Policy` (кроме `/api/docs` и `/api/openapi.json`), `Permissions-Policy`,
  `Cross-Origin-Opener-Policy`, `server_tokens off`, JSON-журнал доступа с `request_id`, предел входов 30 в минуту с
  одного адреса (`429` в формате ошибок API).
- Вход: 5 неудач для пары «почта + адрес» за 300 секунд и 50 с одного адреса закрывают вход (`429`; `LOGIN_MAX_FAILURES`,
  `LOGIN_FAILURE_WINDOW_S`, `LOGIN_IP_MAX_FAILURES`). В журнал входа попадает отпечаток почты, а не почта. Срок токена
  8 часов вместо 12.
- Остановка: backend доделывает открытые запросы до 10 секунд (`stop_grace_period: 20s`); миграции в PostgreSQL идут под
  рекомендательной блокировкой.
- Тест охраны маршрутов: открытыми остаются только перечисленные.
- Журнал событий заявки только дописывается: изменить или удалить событие через ORM нельзя, серия сохранений анкеты по
  тем же полям даёт одно событие за 10 минут.

Прочее:

- README переписан в полное руководство: требования, пошаговый запуск для Windows, macOS и Linux, что делать, если
  что-то не так, архитектура, данные, оценка, безопасность, настройки, тесты. Целевые показатели с замером на стенде —
  в [docs/architecture.md](docs/architecture.md).
- Страница входа в демо-режиме: блок «Как проверить за 10 минут», имя в шаге подставляет учётку в форму.
- Новые сценарии в браузере (`approval-map`, `analyst-card`, `client-fixes`, `feed`, `wizard`, `login-route`, `system`) и
  тесты backend для каждого пункта выше; описание — [docs/test-scenarios.md](docs/test-scenarios.md).
- Ставки продуктов в [docs/scoring.md](docs/scoring.md) расписаны как ключевая ставка 14 % плюс спред продукта
  (8,9 / 5,5 / 10,9 п.п.); значения в каталоге не менялись.

## 1.0.1 — 26.10.2026

- Интерфейс: ровные отступы между карточками и одно главное красное действие на каждом экране.
- Телефон: поправлена вёрстка узких экранов, окно подписания удобно открывать с телефона.
- Слишком большие числа в анкете дают понятную ошибку, а не ошибку сервера.
- Загрузка документов строже проверяет размер и тип файла.
- Воркер быстрее подхватывает задачи, прерванные остановкой.
- Кабинет по умолчанию открыт только с этой машины, в сеть его открывает `FRONTEND_BIND=0.0.0.0`.
- Swagger и демо-учётки есть только в демо-режиме (`DEMO_MODE=true` по умолчанию). Без `SECRET_KEY` вне локального
  окружения backend создаёт случайный ключ при старте.
- Документация переписана; пояснение решения описано в [docs/llm.md](docs/llm.md), примеры документов для загрузки
  лежат в `docs/samples/`.

## 1.0.0 — 26.10.2026

- Сквозной путь клиента: подбор, анкета с данными из ЕГРЮЛ и ФНС, живой статус, решение с причинами, принятие,
  договор с графиком, подпись одноразовым кодом и выдача через эмулятор АБС.
- Небинарные исходы: другие условия со сравнением «вы просили → банк предлагает», другой продукт, запрос
  документов в кабинете.
- Бухгалтер готовит заявку, руководитель подписывает; право подписи сверяется с руководителем по ЕГРЮЛ.
- Подключить компанию может только её руководитель или учредитель по ЕГРЮЛ.
- Условия выдачи для кредита с залогом: документы по залогу и поручительство собственника.
- Кабинет аналитика: карточка оценки, решение в рамках той же политики с обязательным обоснованием, лимит
  полномочий, повтор проверок после сбоя источника.
- Трасса правил, воспроизведение решения на сохранённых признаках и симулятор порогов политики.
- Кредитная политика 1.1: покрытие нового платежа прибылью вместе с нагрузкой к выручке, подбор срока, новые
  поводы для специалиста, истечение предложений и неотвеченных запросов.
- Лента «Новости для вас» из синтетических новостей под отрасль, форму компании и статус заявки.
- Профили риска в эмуляторе по девятой цифре ИНН; ИНН реальных организаций эмулятор не знает.
- Интерфейс переделан целиком: один визуальный язык для клиента и банка, вёрстка для телефона, состояния
  загрузки, ошибки и пустых экранов.
- Необязательное пояснение решения простыми словами локальной моделью, по умолчанию выключено.
- Надёжность: очередь задач конвейера в БД, повторы с растущей паузой, передача специалисту при долгом сбое,
  идемпотентная отправка и выдача.
- CI: тесты на PostgreSQL, сверка документации API с кодом, запуск стенда с нуля, коллекция запросов, сценарии в
  браузере и видео основного сценария.
