# История изменений

## 1.0.0 — онлайн-этап, 26.10.2026

### Сквозной кредитный путь
- Принятие предложения, кредитный договор с графиком, подпись одноразовым кодом в окне подписания
  (смоделированная простая электронная подпись, код хранится только как HMAC и привязан к хешу условий),
  выдача через эмулятор АБС с идемпотентностью по номеру договора, «Мои кредиты».
- Условия выдачи по продукту: для кредита с залогом — документы по залогу и поручительство собственника.
- Бухгалтер передаёт предложение руководителю; право подписи сверяется с руководителем по ЕГРЮЛ.
- Подключить компанию может только её руководитель или учредитель по ЕГРЮЛ.

### Кабинет банка
- Карточка аналитика: причина ручного рассмотрения, балл, грейд, факторы, стоп-факторы, выручка, условия
  «просит → предлагает» с нагрузкой и покрытием.
- Решение аналитика в рамках той же политики, что и у конвейера: обязательное обоснование, лимит полномочий,
  отметка отклонений от рекомендации, повтор проверок после сбоя источника.
- Трасса правил решения и воспроизведение решения на сохранённых признаках.
- Симулятор кредитной политики: пересчёт заявок при других порогах без изменения данных.

### Кредитная политика 1.1
- Покрытие нового платежа прибылью по ФНС (≥ 1,2) вместе с нагрузкой к выручке (≤ 50 %), подбор самого
  короткого подходящего срока, контрпредложение другим продуктом.
- Новые поводы для специалиста: текущая просрочка, выручка только по выписке, нет данных о расходах,
  реорганизация. Точные причины отказа по статусу компании в ЕГРЮЛ.
- Истечение предложений, неподписанных договоров и неотвеченных запросов банка.

### Клиент
- Лента «Новости для вас»: синтетические новости, подобранные под отрасль, правовую форму, регион, продукты и
  статус заявки.
- Очередь аналитика обновляется сама; у каждой вкладки свой вход — клиента и аналитика можно открыть рядом.

### Проверка перед сдачей (после `v1.0.0-rc1`)
- Сквозные проверки в CI на стенде, поднятом командой из README: коллекция запросов через newman и сценарии
  всех демо-учёток в браузере (Playwright) — решения, подпись, выдача и график, кабинет аналитика, лента,
  сбой БКИ.
- Коллекция запросов проходит целиком в Runner и newman: шаги опроса ждут нужный статус сами.
- Демо-учётка `clean@demo.local` с контрпредложением другим продуктом (овердрафт).
- Понятные записи в истории при неверном коде подписи и задержке перевода; текст договора залогового кредита
  совпадает с условиями выдачи; блок условий выдачи не теряет недописанный ответ.
- `docs/product.md`: пользователи и боли, модель процесса, обоснование MVP; документация сверена с кодом.

### Надёжность и сопровождение
- Поток статусов (SSE) не держит соединение с БД; ключ идемпотентности — в рамках заявки; токен без `sub`
  даёт 401; воркер переживает любые ошибки, возвращает зависшие задачи, отправляет «застрявшие» заявки
  специалисту, сообщает о себе healthcheck'ом.
- Эмулятор: профили риска для произвольного ИНН.
- CI: тесты на PostgreSQL, сборка фронтенда, сверка OpenAPI, диаграммы состояний и коллекции запросов с кодом,
  `docker compose up` с нуля и дымовой сценарий.
- Документация: описание API, коллекция запросов, тестовые сценарии, обновлённые архитектура, модель данных,
  диаграмма состояний, правила решения.
